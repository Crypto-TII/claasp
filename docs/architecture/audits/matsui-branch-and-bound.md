# Dependency-free Matsui branch-and-bound audit

## Outcome

CLAASP 5 provides an exact dependency-free Matsui-style search for the reviewed
two-round Speck32/64 XOR-differential slice. It is selected explicitly with
`backend="dependency_free"`; `backend="auto"` retains the existing Kissat
default. The prior single-bit enumeration remains only an incumbent heuristic
and is not part of the optimality argument.

The implementation is deliberately narrower than a generic graph search.
PRESENT, DES, and bitsliced GIFT are benchmarked as independent family
baselines below, but are not described as full Matsui graph adapters.

## Primary algorithm sources

- Matsui, *On Correlation Between the Order of S-boxes and the Strength of
  DES*, EUROCRYPT 1994, [DOI 10.1007/BFb0053451](https://doi.org/10.1007/BFb0053451),
  section 4 and the `Round-2-j` procedure on pp. 370--371. The implemented
  outer recursion corresponds to Matsui's prefix probability multiplied by a
  certified best-possible suffix probability.
- Biryukov, Velichkov, and Le Corre, *Automatic Search for the Best Trails in
  ARX: Application to Block Cipher Speck*,
  [IACR ePrint 2016/409](https://eprint.iacr.org/2016/409), section 3,
  Definitions 1--2 and Propositions 1--2; section 4; and section 5.2,
  Algorithm 1. The implemented inner recursion is the proposition-1
  low-bit-to-high-bit monotone partial `xdp+` bound, specialized to Speck.
- Ji, Zhang, and Ding, *Improving Matsui's Search Algorithm for the Best
  Differential/Linear Trails...*,
  [IACR ePrint 2019/1190](https://eprint.iacr.org/2019/1190), section 2.4,
  Algorithms 1--2, and section 3.1. This supports the weight-domain statement
  and probability-ordered candidate traversal used for cross-checking the
  implementation.

The optimality claim is for a single Markov trail, as in the ARX source. It is
not a claim about a differential hull.

## Implemented bound

For a prefix through round `i`, let `P_i` be its exact rational probability,
and let `B[k]` upper-bound every compatible `k`-round suffix. A branch can
improve a retained incumbent `P_best` only if

```text
P_i * B[n - i] > P_best.
```

The equivalent additive-weight test is

```text
sum(prefix weights) + best_weight[n - i] < incumbent_weight.
```

Equality is safely pruned because the caller supplies a complete retained
witness and CLAASP needs one optimum, not every tied optimum. The current
two-round Speck adapter uses the universally admissible suffix bound `B[k]=1`.
It therefore gains no unproved information from a heuristic lower bound.

Within a modular addition, the search assigns the two input-difference bits
and output-difference bit from least to most significant. The existing
four-state paired-carry recurrence counts the exact compatible input pairs for
each prefix. The partial probability is monotone nonincreasing, so a prefix at
or below the strict improvement threshold is discarded. Complete candidates
are reconstructed with `ModularAddTransitionSemantics` and exact `Fraction`
comparisons; floating-point weights are created only for the public result.

For the first Speck round both input differences are free. Later rounds fix
them from the preceding boundary and branch only over the addition output.
Rotations and XORs propagate the boundary exactly. The returned trail is then
checked independently by `check_speck_trail()` and expanded through the full
component graph by `xor_differential_component_transitions()`.

## Completeness evidence

- For word widths 1 through 5 and thresholds 0, 1/4, and 1/2, tests compare
  every partial-carry result with a separately materialized complete modular
  addition DDT.
- A synthetic two-round transition system compares the generic branch-and-
  bound result with complete Cartesian enumeration and tests strict-bound
  rejection.
- Speck32/64-2 returns weight 1 and the independent graph/wiring checker
  accepts every transition. The solver-backed Kissat path remains an
  independent parity oracle and is not invoked by the dependency-free search.

No Hamming-weight cap, candidate-count cap, pDDT threshold, or sparse-input
restriction affects completeness. Sparse enumeration is used only to find the
initial feasible weight-1 incumbent; every branch capable of beating it is
generated by the monotone carry recursion.

## Representative benchmark matrix

The reproducible command is:

```bash
PYTHONPATH=src python tools/benchmark_matsui_search.py \
  --repeats 10 \
  --output docs/architecture/audits/data/matsui_search.json
```

The committed artifact records the exact environment, median runtime, median
traced peak memory, scope, optimum or bound, and an independent validation flag
for each case.

| Family | Workload | Result | What is validated |
|---|---|---:|---|
| DES | DES-2, all eight 6-to-4 S-boxes | local maximum 1/4; two-round bound weight 2 | rectangular exhaustive DDT and the known active-S-box witness |
| SPN | PRESENT-2 | weight 4 | existing exact dependency-free search and `check_spn_trail()` |
| ARX | Speck32/64-2 | weight 1 | full Matsui search and `check_speck_trail()` |
| bitsliced | GIFT64-1 grouped S-box | probability 3/8 | macro DDT and exhaustive selected-input equivalence of bitsliced and lookup realizations |

The DES row is a nonlinear-round bound plus the two-round Feistel activity
argument, not a generic DES search adapter. The PRESENT row is an independent
SPN baseline, not a relabeling of its existing enumeration as Matsui search.
For GIFT, the entire four-bit Boolean circuit is treated as one macro S-box:
local AND/OR probabilities are not multiplied because reconvergent internal
signals are dependent.

## Deliberate limitations

- Only two-round Speck32/64 XOR-differential search is exposed through the new
  Matsui adapter. Longer-round Speck requires certified nontrivial suffix
  bounds to be useful and remains extension work.
- XOR-linear Speck needs the distinct most-significant-bit-first partial
  correlation recursion from the primary ARX source and is not silently
  approximated by the differential implementation.
- Full DES, general SPN, and bitsliced graph adapters need family-specific
  round or macro-component boundaries. The benchmark baselines establish
  exact transition semantics but do not claim those adapters exist.
- Reduced DES constructors with 2, 4, or 6 S-boxes currently fail graph
  construction; the benchmark uses full eight-S-box DES and does not broaden
  this PR into a primitive-construction repair.
